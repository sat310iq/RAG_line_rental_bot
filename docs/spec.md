# LINE RAG PoC 仕様（軽量 Amplifier 用）

## 目的

LINE 経由の入居者質問に対し、**CSV（FAQ KB）と PDF（基本契約）を階層的に検索**したうえで、根拠に基づく回答または安全なエスカレーション案内を返す。本ファイルは実装の単一の参照点とし、詳細なデプロイ手順は [docs/deploy/](deploy/) を参照する。

## 主ユースケース

- ユーザーが LINE でテキスト質問を送る
- システムが `RAGAnswerer` により検索・回答を生成する
- 信頼度が低い場合はエスカレーションやフォールバック文言で応答する

## 利用者

- 入居者（テナント）
- 運用者・保守者

## 入出力

**入力:** LINE テキスト、（オプション）ユーザー ID、契約 ID 等のメタデータ  
**出力:** ユーザー向け回答テキスト（`render_answer_text` 相当）、必要に応じた次アクション・注意事項

## 優先順位

1. 正確性  
2. 安全性（幻覚・断定の抑制）  
3. 運用上のタイムアウト内での安定応答  
4. 簡潔さ（チャット向け）

## 非目標

- 法的判断の代行  
- 画像・音声の理解  
- 根拠なき長文推論

## 検索・適用ポリシー

- 個別契約・FAQ KB（CSV, `kb_faq`）を**優先**し、不足時に基本契約 PDF を参照する。  
- CSV と PDF が競合する場合は **CSV 優先**（実装・`caveats` の「適用順」に整合）。

## エスカレーション

次の場合は管理会社への問い合わせ等へ誘導する: 根拠不足、ソース競合、低信頼、文書化されていない判断依頼。

## 失敗時

検索・生成が信頼できない場合は**安全なフォールバック**（`Config.fallback_message`）を返し、事実・契約条項を捏造しない。

## 設計・プロセス用ログ（非ランタイム）

`logs/decision_events.jsonl` は**アプリのリクエストログではなく**、ADR やプロセス上の意思決定を人間が追記するためのファイルである（実行時の構造化ログとは別管理）。方針・`.gitignore` との関係は [logs/README.md](../logs/README.md) を参照。
