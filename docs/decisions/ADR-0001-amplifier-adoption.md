# ADR-0001: 軽量 Amplifier 風ワークフローの導入

## ステータス

承認済み（Accepted）

## コンテキスト

LINE RAG PoC は急速に試作が進む一方、設計のドリフトや評価の再現性が課題になりうる。フル Amplifier（多エージェント自動化）は重すぎるため、**ドキュメント駆動・評価データ・意思決定ログ**に限定した軽量版を先に入れる。

## 決定

次を採用する:

1. `docs/spec.md` / `architecture.md` / `eval.md` による仕様・評価の芯  
2. `eval/datasets/line_rag_eval_v1.csv` と `scripts/run_eval.py` による記録可能な評価ラン  
3. ADR（本ファイル）による重要判断の記録  
4. `docs/agents/*.md` によるレビュー観点の共有  
5. **Amplifier CLI・Ragas の本格導入は見送り**（評価フローが安定するまで）

## 設計・プロセス用ログ（非ランタイム）

`logs/decision_events.jsonl` はアプリケーションのリクエストログではなく、ADR や運用上の決定を追記するための**プロセス用**ログである。

## 結果

### 良い点

- 設計の見える化と反復のしやすさ  
- 既存の `run_simple_eval.py` を壊さず併走できる  

### 悪い点

- ドキュメントのメンテ負荷  
- 小さな実験のたびに更新が追いつかないリスク  

## 見送ったもの

- Amplifier CLI の即時統合  
- ドキュメントなしの場当たり開発のみに戻すこと  

## 見直しトリガー

- 評価フローが週次で回るようになったとき  
- レビュー手順のボトルネックが明確になったとき  
- デプロイ前チェックの自動化が欲しくなったとき
