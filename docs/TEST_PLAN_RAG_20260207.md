# ✅ テスト計画書：RAG検索・回答ロジック（CSV優先＋フォールバック）

## 1. テストの目的
以下の仕様に従い、RAGシステムが意図通りに回答を返すことを検証する：

- 検索は FAQ (CSV) を優先
- CSVが「スコア未達」または「該当なし」の場合は PDF にフォールバック
- PDFも該当なしの場合は、固定文言を返す
- CSVにキーワード一致がある場合は、スコアにかかわらずCSVを使う
- キャッシュ更新時に最新のFAQ回答が使われる

## 2. 対象機能

| 機能 | 対象モジュール |
| --- | --- |
| CSV優先判定 | `src/rag_answerer.py` |
| スコア付き検索 | `src/vector_store_manager.py` |
| スコア閾値チェック | `src/rag_answerer.py` |
| 回答生成（summary優先） | `render_answer_text()` |
| キャッシュ無効化 | `src/query_cache.py` |
| fallback文言表示 | `src/config.py` + `.env` |

## 4. テスト実行形式

| 種別 | 実行形式 |
| --- | --- |
| 単体テスト | `pytest` で自動実行可能 |
| 手動確認 | CLIで手動対話 |
| ログ確認 | DEBUGログを確認 |
| キャッシュ | CLI起動 → 再実行検証 |

## 4.1 状況別の推奨対応

| 状況 | 対応 |
| --- | --- |
| テストを自動化して継続実行したい | pytest + LLMモック |
| 今すぐ結果を確認したい（新実装の初期確認） | CLI手動確認で十分 |
| LLMの出力が変動して困っている | モック or 出力差分だけ見る |
| スコア閾値・CSV/PDF優先など分岐条件を明確に保証したい | pytestで実施する |

## 5. テストデータ要件

- `faq_kb.csv` に以下の質問を含む intent を含める：
  - `ペット飼育の可否`
  - `設備_故障`（給湯器/換気扇/エアコン）
- PDFに上記に該当する条文を配置
- `.env` に fallback メッセージと各閾値が設定されていること

## 6. 成功基準

- 全ケースで、期待される回答タイプ（FAQ / PDF / fallback）が正しく選択される
- summaryと根拠が冗長にならず、citation付きで整理されて表示される
- キャッシュを明示的に切り替えた後にFAQが反映される
- fallback文言・スコアログ・キャッシュログが明確に出力されている
