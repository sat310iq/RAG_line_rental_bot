# 賃貸AIチャットボット PoC — プロダクト原則

## プロダクトの本質

「AIで答える」こと自体を目的にしない。**「AIがどこまで答えるべきか」を制御する**プロダクトとする。  
回答精度の最適化より、**責任範囲の設計**を最優先する。

## 技術スタック

- Python / FastAPI / OpenAI API / Chroma
- LangGraph（ルーティング・オーケストレーションに利用する場合）
- Google Cloud Run / LINE Messaging API
- **RAGは極力使わない**（Routing-first 設計）

## 意思決定の優先順位

1. **安全性** — 誤案内・法的リスクを出さない
2. **コスト効率** — LLM 呼び出しを最小化する
3. **挙動の予測可能性** — ブラックボックスを減らす
4. **回答精度**
5. **開発速度**

## 許容できないリスク（実装時に必ず確認）

- 違約金・家賃・責任範囲に関する**不当な断言**
- ハルシネーションによる**誤誘導**
- 個人情報・契約情報の**漏洩**
- 「AIが判断した」と**誤解される**設計（法的・個別条件の最終確定を AI に見せない）

## 実装ルール

- **200行を超える変更**は分割し、レビューしやすい単位にすること（必要なら事前に方針確認）
- **外部依存の追加**は、理由と代替案を提示してから行うこと
- **設計判断が必要なとき**は、選択肢を 2〜3 案に絞り、Pros / Cons を整理したうえで PM 確認を待つこと
- **LLM を呼ぶ前に**、「これはルーティング・ルール・KB で処理できないか」を必ず検討すること

## 制約

- インフラ月額上限：**1万円**（目安）
- フロントエンド実装は対象外
- 自前モデル学習は対象外
- PoC 段階では**過剰な分散設計**は対象外
