# Incident Report: test_tenant_authテストの修正

**Incident ID**: INC-0001  
**Issue ID**: rental_rag_poc-a1b  
**Date**: 2026-01-31  
**Status**: Resolved

## Summary

`test_tenant_auth`テストが失敗していた問題を修正しました。原因は、`TenantAuth._load_tenant_master()`が認証テーブルを使用しない実装に変更されたため、`_tenants`が空のままになっていたことです。

## Observed / Expected

- **Observed**: `test_tenant_auth`が`assert None is not None`で失敗（`_tenants`が空のため）
- **Expected**: テストが正常に通過する

## Root Cause

`TenantAuth._load_tenant_master()`メソッドが意図的にno-op実装に変更されました（認証テーブル不使用のため）。そのため、`self._tenants`は空のままです。

テストコードは古い実装を前提としており、`authenticate('TEST001', '1234')`が成功することを期待していましたが、現在の実装では`_tenants`が空のため、`authenticate()`は常に`None`を返します。

## Resolution

テストを現在の実装に合わせて修正しました：

1. `authenticate()`が`_tenants`が空の場合に`None`を返すことを確認するテストに変更
2. `authenticate_by_pin('777')`が空の辞書を返すことを確認するテストを追加
3. テストコメントに現在の実装の動作を明記

## Changes Made

- `tests/test_masking.py`: `test_tenant_auth()`関数を修正
  - 現在の実装（認証テーブル不使用）に合わせてテストを更新
  - `authenticate()`が`None`を返すことを確認
  - `authenticate_by_pin('777')`が空の辞書を返すことを確認

## Verification

```bash
pytest tests/test_masking.py::test_tenant_auth -v
```

テストは正常に通過しました。

## Prevention

- 実装変更時は、関連するテストも同時に更新する
- テストコメントに実装の意図を明記する
- CI/CDパイプラインでテストを自動実行する

なし（問題は解決済み）
