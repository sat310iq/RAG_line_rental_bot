## 事前確認（6 項目）— テスト開始前・オペレータ確認後に次へ

CHECKLIST の「事前確認」チェックボックス群を、次の **6 項目**に整理して実施する。各項目でオペレータに Yes/No を確認し、**すべて Yes のときのみ**カテゴリ A に進む。

### 1. Cloud Run ステータスおよび最新リビジョン

- `gcloud run services describe line-webhook --region=asia-northeast1`（またはプロジェクトで使用中のリージョン）等で、サービスが稼働していること。
- **現在トラフィックが向いているリビジョン**を記録する（CHECKLIST に例として `line-webhook-00018-sbq` が載っている場合は**例示**であり、実際のリビジョン名はコマンド出力で確定すること）。
- オペレータ確認: 「上記リビジョンでテストしてよいか」

### 2. Webhook URL および検証

- LINE Developers Console で Webhook URL が対象環境の Cloud Run に向いていること（**URL の値やシークレットをチャットに貼らない**）。
- Webhook の「検証」で **200 OK** であること（オペレータが Console で確認）。
- オペレータ確認: 「検証 200 OK 済みか」

### 3. pytest 全件パス

- リポジトリルートで `python3 -m pytest tests/ -q`（またはプロジェクト標準の全件コマンド）を実行し、**失敗 0** であること。
- オペレータ確認: 「pytest 結果を承認するか」

### 4. チェックリスト件数・カテゴリ整合

- `LINE_TEST_CHECKLIST.md` の **判定基準表**に従い、対象件数が次と一致することを口頭または記録で確認する。  
  - **A: 20 / B: 24 / C: 4 / D: 2 / E: 5 / F: 4 → 合計 59 件**（CHECKLIST 本文の「テスト後の記録」テンプレートの内訳と一致）。
- オペレータ確認: 「59 件すべてをこのセッションでカバーするか」

### 5. eval_log.md の記録済み確認

- `docs/eval_log.md` を開き、**直近の品質ゲート／本番 Eval（Metrics v2）等**、リリース判断に必要な記録が存在するか確認する（なければオペレータ判断で追記してから手動テストに進むか決める）。
- オペレータ確認: 「eval_log の状態で手動テストに進んでよいか」

### 6. 依存基盤およびテスト用 LINE

- CHECKLIST 記載のとおり: **Semantic Cache（Redis）起動中**、**FAISS インデックスがロード済み**（Cloud Run 上の想定含む）、**テスト用 LINE アカウントで Bot が友だち追加済み**。

## 結果の記録形式

### カテゴリごと（必須）

```text

不合格:
  - ID: 入力クエリ要約
  - 期待: （CHECKLIST から 1 行）
  - 実際: （応答の要約。秘密・個人情報はマスク）
  - 判定理由: （断定 NG / 数値含有 / キャッシュ遅い / 等）
```

- **B:** サブ B-1〜B-6 ごとにまとめてもよいが、**B-6 は項目別に必ず記載**する。  
- **D:** 不合格が 1 件でもあれば **「即停止・リリース禁止」** を明示し、以降のカテゴリは「未実施」と記載する。
